# 2026-11-05 user 性能测试

## 目标

看用户主键读取、令牌校验和登录在 10 万用户下的耗时。不并发。

- 按用户 ID 读一个用户，一次读 20 个，按用户 ID 搜索。
- 校验同一条令牌：缓存没有、只在 Redis、已经在本进程。
- 登录 10 次，看密码校验的耗时。

## 范围

只打 user 的逻辑和存储。不经过网关。开发库 `suim` 没有写入。

## 环境

- 日期：2026-11-05
- 库：本机 MySQL `127.0.0.1:3306` 上的 `suim_user_bench`，表结构来自 `migrations/user.sql`
- 10 万用户，编号 `u0000001` 到 `u0100000`。密码哈希相同，登录密码固定
- 热用户 `u0000001` 有一条平台 1 的令牌。登录性能测试走平台 2，不顶掉这条令牌
- 令牌校验的本地缓存是 100 个槽、每槽 2000 条，和 `user.yaml` 里的 `localCache` 一样
- 每个查询记 30 次，登录记 10 次
- 命令：`go test -tags perf ./services/user/ -count=1 -timeout 180s -run TestPerfUser`
- 开始时清空这个库的 `user` 和 `auth_tokens`。结束时删掉这场写出的 Redis 令牌键。不执行 `FLUSHDB`

## 结果

2026-11-05 通过，整场 8.23s，其中灌数 6840ms。耗时单位是毫秒。

| 查询 | 最小 | 中位 | 最大 | 执行计划 |
| --- | --- | --- | --- | --- |
| 按用户 ID 读取 | 0.315 | 0.453 | 0.711 | `PRIMARY`，`const`，估计 1 行 |
| 一次读 20 个用户 | 0.521 | 0.628 | 1.059 | 同主键 |
| 按用户 ID 搜索 | 0.378 | 0.520 | 0.848 | 同主键 |
| 按邮箱读取 | 未单独计时 |  |  | `idx_email`，`const`，估计 1 行 |
| 令牌校验，不走本地缓存，每次先删掉 Redis 快照 | 1.631 | 1.944 | 2.952 | `idx_token_hash`，`ref`，估计 1 行 |
| 令牌校验，本地未命中、Redis 有快照 | 0.795 | 0.983 | 1.431 | 30 次都是本地未命中 |
| 令牌校验，本地已命中 | 0.447 | 0.638 | 0.777 | 30 次都是本地命中 |
| 登录 | 75.147 | 79.111 | 84.640 | 时间主要在密码校验 |

本地命中之后仍然要按主键读用户行，所以它和「按用户 ID 读取」接近，不会掉到微秒级。用户资料本身没有做本地缓存。
