# 2026-11-05 group 性能测试

## 目标

看大群上的读在单线程下要多久，以及本地缓存吃掉了哪几条。不并发。

## 环境

- 日期：2026-11-05
- 库：本机 MySQL `127.0.0.1:3306` 上的 `suim_group_bench`，表结构来自 `migrations/group.sql`
- 大群 `g0000001`：5000 名成员，群主 `u0000001`，成员版本 5000
- 群主另外还在 200 个小群里，已加入的群一共 201 个
- 大群有 2000 条待处理入群申请
- 每个查询先跑通，再记 30 次的最小、中位、最大
- 本地缓存使用单独频道 `suim:group:bench:delete`，不碰正在运行的 group 进程
- 命令：`go test -tags perf ./services/group/ -count=1 -timeout 180s -run TestPerfGroup`
- 跑完清空 `suim_group_bench` 的表。库留着

## 结果

2026-11-05 通过，整场 2.40 秒，其中灌数 365 毫秒。耗时单位是毫秒。没有本地缓存的是直接读 MySQL。

| 查询 | 最小 | 中位 | 最大 |
| --- | --- | --- | --- |
| 群资料 | 2.112 | 2.400 | 3.053 |
| 单个成员 | 2.343 | 2.604 | 3.289 |
| 成员第一页，20 条 | 6.697 | 7.244 | 7.868 |
| 成员深分页，偏移 4980 | 8.521 | 9.119 | 10.236 |
| 一次取出 5000 个成员 ID | 6.616 | 7.383 | 8.282 |
| 已加入的群第一页 | 5.831 | 6.487 | 7.509 |
| 增量，版本 0 | 2.574 | 2.986 | 3.395 |
| 增量，距最新 50 | 4.359 | 4.980 | 6.022 |
| 增量，距最新 500 | 3.553 | 3.999 | 5.007 |
| 入群申请第一页，共 2000 条 | 4.849 | 5.145 | 5.766 |
| 群资料，本地缓存 | 0.000 | 0.000 | 0.010 |
| 单个成员，本地缓存 | 0.000 | 0.000 | 0.003 |
| 5000 个成员 ID，本地缓存 | 0.491 | 0.596 | 1.132 |

群资料和单个成员命中本地缓存后，这一跳已经小于 0.01 毫秒。成员 ID 列表命中后仍要做一次 5000 个 ID 的哈希，所以停在 0.6 毫秒。

成员分页、已加入的群、申请列表没有缓存。5000 人的成员页中位 7.2 毫秒，深分页 9.1 毫秒。版本 0 和距最新 500 都只返回全量标记，不把成员资料带回，所以比距最新 50 还快。距最新 50 要再查出这 50 个人。
